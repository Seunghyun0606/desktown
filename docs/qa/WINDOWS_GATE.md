# DeskTown v0.1 — Windows 내보내기 빌드 검증 게이트

Godot 편집기, Linux 헤드리스 CI, Windows 내보내기 성공만으로 실제 창과 입력 동작을 보장할 수 없다. 반드시 내보낸 빌드에서 검사한다. 아래 입력 매트릭스를 기록하고 검토하기 전까지 일반 Focus에서 Ghost를 활성화하지 않는다. CI는 Windows 실행기에서 내보낸 실행 파일을 헤드리스로 실행하고, 분리된 세 프로세스에서 임시 저장 데이터의 생성·복구·재읽기를 검사한다. 이 검사는 눈에 보이는 창의 동작, 일반 Windows 저장 위치, 실제 잠금·절전 이벤트까지 증명하지 않는다.

## 빌드 받기와 실행

현재 로컬 전달본은 일상 Focus MVP를 바탕으로 한 `build/DeskTown-QA-2026-10-18.zip`이다. 게임 파일은 검증된 2026-10-13 빌드와 같고 QA 안내·도구만 갱신했다. 압축을 새 빈 폴더에 전부 풀고 **Prepare-QA.cmd**로 사전 검사와 새 `qa-reports` 결과 양식을 만든다. 게임 패키지 SHA·실행 코드 SHA·QA 도구 SHA는 `qa-handoff.json`과 보고서에서 구분한다. 이전 CI 키트도 아래 절차로 검사할 수 있다.

1. [CI Actions 페이지](https://github.com/Seunghyun0606/desktown/actions/workflows/ci.yml)에서 **성공한 최신 `main` 실행**을 열고 커밋 SHA와 실행 URL을 기록한다.
2. `desktown-windows-qa-kit` 아티팩트를 내려받아 압축을 풀고 PowerShell에서 `./preflight.ps1 -RunSmoke`를 실행한다. 이 스크립트는 버전이 붙은 ZIP과 전체 파일 목록을 검증하고, 개인 저장 데이터를 건드리지 않는 별도 저장·재시작·복구 검사를 수행한다. Windows 11에서 `./app/DeskTown.exe`를 실행한다. `desktown-windows-prototype-package`는 배포용 ZIP이고 `desktown-windows-foundation`은 원본 내보내기 결과다. ZIP 안에서 실행 파일을 직접 실행하지 않는다.
3. 노트북의 실제 Windows 배율을 넣어 `./collect-evidence.ps1 -Scaling '100%'`를 실행한다. 빌드 SHA, OS 버전, 모니터 경계가 포함된 로컬 결과 양식이 만들어진다. 파괴적인 복구 검사 전에는 별도 Windows 테스트 계정을 사용하거나 기존 DeskTown 저장 데이터를 백업한다. 검사 회차별 아티팩트와 저장 기준 상태를 구분한다. 개인 저장 데이터나 업무 내용은 업로드하지 않는다.

처음 실행하면 개인정보 안내와 온보딩 화면이 나타난 다음 Town으로 이동한다. Town에서 Focus 설정을 연다. Focus 설정에는 PiP Companion, Minimized, Hidden 중 하나를 선택할 수 있고 Ghost는 비활성화되어 있다. PiP는 작은 창만, Minimized는 Town 작업 표시줄 항목만, Hidden은 트레이만 남긴다. 트레이에는 열기, 모드·설정, Focus 종료, 앱 종료가 있다. **Focus 세션이 없을 때만** Town에서 F10을 누르면 Ghost QA 미리보기가 켜진다. 이 동작으로 세션이나 보상이 생기지 않는다. 같은 조건에서 F8은 Companion 플레이스홀더 동작을 순환한다.

## 1. 기본 진행과 복구

키트의 `Start-QA.cmd`는 개인 저장 대신 초기 온보딩 복사본으로 실행한다. 같은 버튼을 다시 실행하면 `qa-sessions/focus`의 상태를 재개한다. 이 경로로 Focus·설정·강제 종료·복구를 먼저 검사하고, 일반 `user://` 위치 확인은 별도 계정 또는 백업 후 직접 앱을 실행해 검사한다. 자세한 명령은 키트 `QA-README.md`에 있다.

| 검사 | 절차 | 통과 조건 | 결과 / 근거 |
| --- | --- | --- | --- |
| 첫 실행 | 온보딩 완료 후 Focus 설정 열기 | Start 이후에만 활동 기록 시작, 앱 선택은 선택 사항 | |
| 세션 유지 | PiP에서 25분 Focus를 시작하고 트레이로 Minimized → Hidden → PiP 전환 | 경과 시간, Energy, Workshop 진행이 이어지고 세션이 중복되지 않음 | |
| 조용한 완료 | 각 표시 모드에서 다른 앱을 쓰는 동안 세션 완료 | PiP는 숨겨지고 트레이에 완료 상태 표시; Minimized의 Town은 최소화 유지, Hidden은 숨김 유지; Town이 자동으로 열리지 않고 알림 또는 트레이 표시가 작업 앱의 포커스를 빼앗지 않음 | |
| 알림 없는 완료 | 트레이에서 `Completion notice`를 끄고 다음 세션 완료 | 알림 창이 없고 트레이에서 완료 상태와 Open을 사용할 수 있으며 재시작 후 설정 유지 | |
| 알림 열기 | 완료 알림의 `Open DeskTown` 클릭 | 기존 Town이 한 번 열리고 프로세스나 보상 중복 없음 | |
| 보상 지연 표시 | 완료 후 트레이에서 DeskTown 열기 | Workshop 연출과 Railway 예고가 순서대로 한 번씩 표시 | |
| 연출 중 재시작 | 별도 실행에서 완료 알림 후, 연출 중, 발견 이벤트 중 종료·재실행 | 저장된 상태에 맞는 대기 단계가 한 번 이어짐 | |
| 완료 후 일상 Focus | Start-Daily-Focus 또는 Workshop·지도 확인 후 Focus with Mina → 25/45/60분 선택·실제 세션 완료 | 일일/총 시간만 추가되고 Workshop은 완성 유지; 보상·지도 중복 없음, 다음 Focus 가능 | |
| 반복 세션 격리 | Start-Play와 Start-Daily-Focus 각각 실행·종료·같은 버튼 재실행 | play/daily 저장이 서로 섞이지 않고 각각 기존 진행 재개 | |
| 새 세션 차단 | 대기 보상·지도·복구 선택 중 새 Focus 진입, 활성 세션 중 중복 Start | 미해결 단계가 유지되고 두 번째 세션/저장 주체를 만들지 않음 | |
| 복구 | 세 표시 모드 각각에서 Focus 시작, 체크포인트 대기, 프로세스 종료 후 재실행 | Resume/End 선택이 나오고 종료 중 시간은 제외; Resume 뒤 선택한 표시 모드로 복귀 | |
| Windows 수명주기 | 별도 세션에서 잠금/해제, 연결 해제/재연결, 절전/복귀 수행; 잠금과 절전 겹침도 검사 | 중단 시간이 제외되고 모든 중단 사유가 해소된 뒤 새 기준점에서 재개하며 복구 가능 | |
| 중복 실행 | 첫 `DeskTown.exe`가 실행 중일 때 두 번째 실행 | 기존 인스턴스가 열리고 두 번째 Focus·저장 주체는 생기지 않음 | |
| Minimized 자원 | Minimized로 전환 후 창 목록과 작업 관리자 확인 | Town은 작업 표시줄에 최소화되고 Companion/Ghost 창이나 활성 시각 효과 없이 타이머는 계속 동작 | |
| Hidden 자원 | Hidden으로 전환 후 창 목록과 작업 관리자 확인 | Town 작업 표시줄 항목과 Companion/Ghost 창 없이 트레이만 남고 타이머는 계속 동작 | |
| 작업 표시줄 복원 | Focus 중 또는 완료 후 최소화된 Town의 작업 표시줄 아이콘 클릭 | 기존 Town이 한 번 열리고 Focus 중이면 같은 세션이 이어지며, 완료 후에는 대기 중인 보상만 표시 | |

차이가 나면 정확한 경과 시간과 저장 상태를 기록한다. 알림을 표시하거나 클릭할 수 없다면 **트레이 → Open DeskTown**을 사용하고 실패를 기록한다. 저장된 보상은 유지돼야 한다.

## 2. Companion과 위치

Windows 배율 100%, 125%, 150%에서 단일·듀얼 모니터를 검사한다. 모니터별 DPI가 다르거나 보조 모니터가 기본 모니터 왼쪽에 있는 경우도 포함한다.

| 검사 | 통과 조건 | 결과 / 근거 |
| --- | --- | --- |
| 최상단 표시와 드래그 영역 | 일반 앱 창 위에 Companion이 보이고 지정된 상단 영역만 드래그 가능 | |
| 포커스와 입력 | Companion을 띄운 상태에서 Chrome, VS Code, Excel, Notion 사용 가능 | |
| 닫기 | Focus를 끝내지 않고 Hidden(트레이만)으로 전환 | |
| 배율 프리셋 | Focus 설정에서 75/100/125/150%를 선택하고 PiP 안의 −/+ 버튼 및 트레이에서도 변경; 각 크기에서 읽을 수 있고 화면 안에 표시 | |
| 위치 복원 | PiP 상단을 드래그해 이동한 뒤 잠시 기다리고 재실행; 선택 모니터 연결을 해제한 뒤 재실행 | 이동 위치가 저장되며, 모니터가 없으면 사용 가능한 작업 영역 안으로 보정 | |

## 3. Ghost 입력 게이트 — 출시 차단 조건

Town에서 F10으로 분리된 미리보기를 표시하고 트레이에서 모서리 위치, 모니터, 불투명도 40/65/85%를 조절한다. Windows 11의 배율 100%, 125%, 150%, 단일·듀얼 모니터, 각 앱의 창 모드·최대화 모드에서 반복한다. Mina·소품이 보이는 픽셀과 투명한 픽셀 모두를 앱 위에 올려 검사한다.

| 앱 | 클릭 / 더블클릭 / 우클릭 | 호버 / 드래그 | 스크롤 / 텍스트 선택 | 키보드 포커스 | 투명도 / 최상단 / Alt+Tab | 결과 / 근거 |
| --- | --- | --- | --- | --- | --- | --- |
| Chrome | | | | | | |
| VS Code | | | | | | |
| Excel | | | | | | |
| Notion | | | | | | |

각 DPI·모니터·창 상태 조합에서 포인터 동작이 모두 아래 앱에 도달하는지, 입력 포커스가 유지되는지, Ghost가 투명하고 최상단인지, 일반 작업 창처럼 작업 표시줄/Alt+Tab에 나타나지 않는지 기록한다. 표시 중 위치·불투명도 변경과 재시작 후 위치 복원도 확인한다.

**판정:** 입력 가로채기, 포커스 탈취, 화면 밖 표시, 불안정한 네이티브 동작 중 하나라도 있으면 실패다. Ghost를 Focus 설정과 트레이에서 비활성 상태로 두고 Hidden을 사용한다. 정확한 조합과 재현 단계, 스크린샷/영상을 이슈에 남긴다. F10 미리보기 통과는 플랫폼 시제품의 근거이며, Ghost를 일반 Focus 모드로 켜려면 내보낸 빌드에서 전체 흐름과 안전한 대체 동작을 추가 확인해야 한다. 담당자, 날짜, 빌드 SHA, 최종 판정을 기록한다.

## 4. 펀딩용 빌드 게이트

시각 38개·음향 8개는 승인·연결됐고 재현 가능한 캡처와 native 검사가 있다. 실제 Windows 플레이·장치 청취 결과를 아래에 별도로 기록한다.

| 검사 | 통과 조건 | 결과 / 근거 |
| --- | --- | --- |
| 시각·행동 | Workshop 3상태·Town NPC 개별 이동·Mina 작업 휴식·Companion 접촉이 읽히고 모달 글자/버튼이 가려지지 않음 | |
| 음향·음량 | 실제 출력 장치에서 Town 주변음·새·발소리·작업대 타격·버튼·완성·발견의 타이밍과 음량이 적절함 | |
| 음소거·정지 | Tray Audio off 즉시 무음, 재시작 후 유지; 숨김·최소화·잠금 중 해당 소리 중지, 복귀 시 몰아 재생 없음 | |
| 효과 감소 | Tray Reduced motion 설정·재시작 후 유지, 선택적 이동/스트레칭과 효과 감소 | |
| 깨끗한 Windows 11 | 편집기·SDK 없는 테스트 계정에서 전체 ZIP 압축 해제·실행·종료·재실행; 사용한 환경을 기록 | |
| 기본 저장 위치 | 테스트 계정에서 직접 EXE 실행, 실제 일반 저장이 앱 폴더 밖에 있고 쓰기·백업·복원이 가능; 개인 데이터 미첨부 | |
| ZIP 업데이트·롤백 | 앱 종료·백업 후 별도 폴더에서 같은 호환 V1 진행을 재개; 사용 중인 저장 덮어쓰기 없음 | |

로컬 실행·CI·양식 생성만으로 깨끗한 PC, 입력/DPI, 잠금/절전, 실제 장치의 통과를 추정하지 않는다. 설치·서명·자동 업데이트 방식은 별도 인간 결정이며 이 ZIP 검증을 이유로 활성화하지 않는다.
