# DeskTown 로컬 내보내기 종료 문제 후속 검사 — 2026-10-09

## 대상과 재현

게임 소스 기준 커밋은 `8f530ae2abaf58a940047255b830f005d1a5fa25`다. 이번 변경은 로컬 내보내기 도구·검사·문서이며, 아래 실행은 미커밋 작업 트리에서 수행했다. [10월 5일 기록](QA_EXECUTION_2026-10-05.md)의 내보내기 정체를 조사했다.

1. 기존 임시 SDK 폴더에는 SDK 파일이 없어 런타임 초기화가 실패했다. 이 시도는 내보내기 정체 재현으로 판정하지 않는다.
2. SDK 8.0.425를 한글이 포함된 저장소 아래 설치하면 Godot이 SDK 경로의 한글을 `??`로 읽고 MSBuild 초기화 오류를 기록했다. 명령은 종료 코드 0으로 끝났으므로 종료 코드만으로는 성공을 판정할 수 없다.
3. 같은 SDK를 영문 경로 `%LOCALAPPDATA%/DeskTownBuildTools/dotnet-8.0.425`에 복사한 뒤 콘솔 래퍼로 실행했다. 게시·패키지 생성·Godot 본체 종료 로그는 완료됐지만, 60초 후에도 콘솔 래퍼와 해당 게시에서 시작한 MSBuild/VBCSCompiler 작업자가 남아 있었다. 해당 실행의 래퍼를 제한 시간에 중단했다.

프로세스와 로그 관측은 [Godot 이슈 #110101](https://github.com/godotengine/godot/issues/110101)에 보고된 콘솔 래퍼의 자식 빌드 서버 대기 현상과 일치한다. 최초 10월 5일 실행에는 전체 진단 로그가 없어 당시 원인이 같았다고 확정하지 않는다. 이번 원본 증거는 `build/export-diagnostic-2026-10-09/`에 보관했다.

## 적용한 해결과 검사

`scripts/export_windows.py`는 콘솔 래퍼 대신 같은 폴더의 Godot 본체를 직접 실행한다. 고정 도구 버전, 영문 SDK 경로, 빈 출력 폴더를 검사하고, 해당 프로세스에만 빌드 작업자 재사용 중지 환경 변수를 적용한다. 제한 시간·전체 로그·오류 검사·필수 배포 파일 확인을 통해 부분 파일이나 종료 코드 0의 오류 실행을 실패로 처리한다.

| 항목 | 결과 |
| --- | --- |
| 새 도구의 Windows Release 내보내기 | 10.42초, 종료 코드 0, 오류 로그 없음, 196개 파일 |
| 새 빌드의 분리 저장 `write` → `recover` → `check` | 세 단계 모두 종료 코드 0, 성공 마커, Godot 오류 없음 |
| 도구 회귀 검사 | 7개 통과: 오류 로그, 비정상 종료, 부분 파일을 남긴 시간 초과, 누락된 DLL, 출력 경계, 기존 파일 보존, 정상 로그 |
| 저장소 구조·`git diff --check` | 통과 |
| 검사 후 Godot/DeskTown 프로세스 | 남아 있지 않음 |

출력 폴더는 `build/windows-local-2026-10-09/`다. `DeskTown.exe` SHA-256은 `83cadc0e4cda27b85213f0e636f20f39ef5165caaf37be16fbe54add3d5e3b42`다. 실행별 도구 로그·결과는 `build/export-logs/20261009-193441-b825a19f/`, 분리 저장 검사 로그는 `build/export-smoke-2026-10-09/`에 보관했다. 이번 실행은 개인 저장 위치를 사용하지 않았다.

## 남은 검증

로컬 내보내기 정체를 우회하는 도구와 자동 검사는 완료했다. 실제 Windows의 PiP 크기·드래그, 최소화·복원, 숨김·트레이, 다른 앱 입력·포커스, DPI·다중 모니터 검증은 여전히 미검증이다. 이전에 거절된 실사용 QA 판정 요청을 재요청하거나 통과로 처리하지 않았다. 이번 로컬 출력은 공식 CI QA 키트나 출시 승인 산출물이 아니다.
